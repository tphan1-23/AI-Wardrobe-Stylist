## What the tests cover

- Input validation (email, password, name, household name, invite code, location) including boundaries and malicious-looking input.
- Every success and failure path of sign-up, log-in, log-out, create household, join household, save location and overview loading, with the server replaced by an in-memory fake.
- The onboarding state machine: household, then location, then ready.
- The Supabase adapter: correct RPC names and argument names, queries scoped to the signed-in user's own row, errors never returning data.
- Error mapping to friendly messages, and network failures.

## What is not covered, and why

- React Native screens (`AuthScreen`, `HomeScreen`, household screens) and `useSession` are not unit-tested: they need a device or emulator. They contain no business logic; the logic lives in the files above.
- `frontend/src/services/supabase.ts` (real client construction) is not covered for the same reason.
- No test talks to a real Supabase project; the database functions and row-level security in `supabase/migrations/0001_init.sql` are checked only for consistency with the tag schema, not executed.
